# Go Code Generation — `protoc-gen-codec-go`

This document covers how `protoc-gen-codec-go` emits serialization code
for Go targets. For language-neutral design rationale, see
[`../architecture.md`](../architecture.md).

## Generated Methods

For each proto message annotated with `codec.type`, the generator emits
a `<basename>.codec.go` file next to the `.proto` source containing the
following receiver methods on the target type:

```go
func (m *T) MarshalCodec() ([]byte, error)
func (m *T) MarshalToCodec(buf []byte) (int, error)
func (m *T) UnmarshalCodec(data []byte) error
func (m *T) SizeCodec() int
func (m *T) ResetCodec()
```

| Method        | Role                                                                       |
|---------------|----------------------------------------------------------------------------|
| `MarshalCodec`   | Allocates a buffer of `SizeCodec()` bytes and marshals into it.               |
| `MarshalToCodec` | Marshals into a caller-provided buffer. Zero-alloc. Returns bytes written. |
| `UnmarshalCodec` | Reads proto wire format field-by-field into the receiver's fields.         |
| `SizeCodec`      | Computes the exact serialized size without allocating.                     |
| `ResetCodec`     | Zeroes serialized fields for `sync.Pool` return.                           |

Output files are marked `// Code generated by protoc-gen-codec-go. DO NOT EDIT.`

## Field Mapping

Mapping from a proto field to its Go counterpart is driven by the proto
wire type plus the `codec.*` annotations.

| Proto declaration                                                            | Go result                                                        |
|------------------------------------------------------------------------------|------------------------------------------------------------------|
| `uint32 kind = 1 [(codec.cast) = "Kind"]`                                    | `m.Kind = Kind(v)`                                                |
| `sfixed64 amount = 2 [(codec.cast) = "Fixed64"]`                             | `m.Amount = Fixed64(v)`                                           |
| `bytes ref = 3 [(codec.cast) = "Digest", (codec.fixed_len) = 32]`            | strict 32-byte check, then `copy(m.Ref[:], v)`                    |
| `string id = 4 [(codec.field) = "ID"]`                                       | `m.ID = string(v)` (always copied)                                |
| `repeated string tags = 5`                                                   | `m.Tags = append(m.Tags, s)`                                      |
| `repeated uint32 nums = 6`                                                   | proto3 packed; `m.Nums = append(m.Nums, ...)`                     |
| `map<string,string> attrs = 7`                                               | `m.Attrs[k] = v`                                                  |

Without `codec.field`, the generator falls back to PascalCase conversion
of the proto field name. Without `codec.cast`, the wire type maps
directly to the native Go type (`int64` → `int64`, `string` → `string`,
etc.). A field whose Go target is not the obvious wire-type mapping must
declare a cast — otherwise generation fails.

## Enums

Proto enums map to Go integer enums by cast:

```protobuf
enum Status {
  STATUS_UNSPECIFIED = 0;
  STATUS_PENDING     = 1;
  STATUS_RUNNING     = 2;
  STATUS_COMPLETED   = 3;
}
```

The leading `*_UNSPECIFIED = 0` is mandatory (both a proto3 requirement
and the convention the generator relies on). Wire value 0 maps to the
Go zero value — typically an invalid sentinel — and non-zero values
map to the corresponding Go constants without offset.

A field referencing an enum uses `codec.cast` to name the Go type:

```protobuf
uint32 status = 1 [(codec.field) = "Status", (codec.cast) = "Status"];
```

## Oneof

Oneof fields serialize only the populated branch. The generator does
not introduce a wrapper type for the oneof; the Go struct continues to
carry the branch fields directly. `MarshalToCodec` writes exactly one
branch based on the target type's existing discriminator (for example
a companion enum field). `UnmarshalCodec` reads the wire tag and writes
into the correct Go field.

## String Handling

Strings and byte slices are always copied out of the input buffer
during unmarshal. No `unsafe.String` aliasing, no lifetime coupling
between the decoded message and the wire buffer. Once `UnmarshalCodec`
returns, the input buffer is safe to recycle.

To keep the allocation cost low, the generator classifies each message
at generation time and selects one of three unmarshal strategies:

| Mode         | When selected                                           | Behaviour                                              |
|--------------|----------------------------------------------------------|---------------------------------------------------------|
| `slabNone`   | Message has no `string` fields                          | Per-field allocation (no slab needed).                  |
| `slabNaive`  | Message has `string` fields but no `bytes` fields       | Single slab backing all string fields.                  |
| `slabSmart`  | Message has both `string` and `bytes` fields            | Slab shared between strings and transient byte copies.  |

The classification is performed once per message from the schema, so
the hot path carries no runtime branching to pick a strategy. The
selected mode is an implementation detail — callers see identical
semantics in all three cases.

## Reset Semantics

`ResetCodec` zeroes every serialized field so the message can be returned
to a `sync.Pool`:

- Scalar fields are set to their zero value.
- String fields are set to `""` (releases the backing string reference).
- Slice and map fields are set to `nil`, releasing the backing array.
- Fields annotated with `(codec.keep_capacity) = true` are reset to
  zero length while preserving the backing array (`s = s[:0]`) so the
  next user of the pooled object reuses the same buffer.

After zeroing the serialized fields, `ResetCodec` checks whether the
receiver implements a `ResetInternal()` method and invokes it if so:

```go
if ri, ok := any(m).(interface{ ResetInternal() }); ok {
    ri.ResetInternal()
}
```

This gives hand-written types a hook for clearing unexported state
(caches, indexes) that the schema doesn't know about. Types without
internal state simply omit the method.

## Running the Generator

Build the plugin binary:

```bash
make build
```

Invoke it through protoc directly or via `go:generate`:

```bash
protoc \
  --plugin=protoc-gen-codec-go=./bin/protoc-gen-codec-go \
  --codec-go_out=. --codec-go_opt=paths=source_relative \
  -I <proto-root> \
  mytype.proto
```

A common pattern is to co-locate a `.proto` file with the Go package
it describes and add:

```go
//go:generate protoc --plugin=protoc-gen-codec-go=... --codec-go_out=. mytype.proto
```

Generated `.codec.go` files are written next to their `.proto` source.

## Runtime Dependency

Generated Go code imports a single runtime package:

```go
import "go.stealthscale.io/protoc-gen-codec/lang/go/codec"
```

The package provides wire primitives and sentinel errors. It has no
dependencies beyond the standard library.

## Testing

Go targets are tested with:

- **Roundtrip** — `MarshalCodec` → `UnmarshalCodec` yields a struct equal
  to the input under `reflect.DeepEqual`.
- **Size accuracy** — `SizeCodec()` equals `len(b)` from `MarshalCodec`.
- **Reset completeness** — after `ResetCodec`, the receiver equals its
  zero value for all serialized fields.
- **Property-based fuzzing** — `pgregory.net/rapid` generates
  randomised inputs covering varint boundaries, packed scalars, oneof
  branches, and fixed-length guards.
- **Benchmarks** — `MarshalToCodec` targets zero allocations;
  `UnmarshalCodec` targets a single slab allocation for messages eligible
  for the slab strategy.

The reference fixture lives at `lang/go/integration/` and exercises enum
casts, fixed-length byte arrays, repeated strings, and oneof-like
patterns.
